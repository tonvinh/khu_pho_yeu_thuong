## A1 · Banner báo tin in-web bị nền hero phủ kín

**Hiện tượng.** Sau khi admin bấm "Đã treo biển", tác giả tải lại trang chủ. Trong DOM có đủ ba
banner ("🎉 Câu của bạn đã được treo tại Hẻm QC 1!" và hai banner "Chúc mừng! … đã được duyệt")
nhưng màn hình chỉ thấy một mảng cam trống ở đúng vị trí đó. Nút "Chia sẻ", "Đề xuất lại",
"Đóng" đều không bấm được.

**Nguyên nhân gốc.** Trong `src/components/home/HomeShell.tsx`:

- Dòng 155–158: lớp nền hero là `absolute inset-x-0 top-0 h-[620px] … sm:h-[900px]`.
- Dòng 239: khối banner là `<div className="bg-[var(--kp-hero-from)] px-4 pt-4 sm:px-6">` —
  **không có `relative`**, tức `position: static`.

Trong cùng một stacking context, phần tử `absolute` luôn vẽ đè lên phần tử `static`, bất kể thứ
tự DOM. Thanh nav ngay phía trên (dòng 163) có `relative` nên không bị dính; banner thì có.

**Kiểm chứng.** `document.elementFromPoint` tại tâm banner trả về đúng div gradient chứ không
phải banner.

**Cách sửa.** Thêm `relative` cho khối banner:

```diff
-        <div className="bg-[var(--kp-hero-from)] px-4 pt-4 sm:px-6">
+        <div className="relative bg-[var(--kp-hero-from)] px-4 pt-4 sm:px-6">
```

**Nghiệm thu.**
1. Chạy hết luồng tới bước "Đã treo biển" (xem §E để lấy lại dữ liệu test).
2. Tải lại trang chủ bằng tài khoản tác giả → banner hiện rõ trên nền cam.
3. Bấm "Chia sẻ" mở đúng `/bien/{id}`; bấm "Đóng" gọi `PATCH /api/v1/me/notifications/{id}`.
4. Đây là **E2E-1 bước 14** trong `docs/19` — đánh dấu pass.

**Rà thêm khi sửa.** Soát mọi con trực tiếp khác của `<div className="relative">` ở dòng 154 xem
còn khối `static` nào nằm trong vùng 620/900px đầu trang không.

# PHẦN B — Trung bình

## B1 · Import CSV mã UTF-8 không BOM bị đọc sai

**Hiện tượng.** Nạp CSV UTF-8 thường: dòng hợp lệ `Xom Import OK, Thành phố Hồ Chí Minh,
Phường Bàn Cờ` vẫn báo *"Tỉnh/Thành phố không có trong danh mục 34 tỉnh/thành"*. Nhãn dòng in ra
`ThÃ nh phá» Há» ChÃ­ Minh` — dấu hiệu kinh điển của việc giải mã UTF-8 bằng latin-1.

**Đối chứng đã chạy.**

| File | Kết quả |
|---|---|
| `.xlsx` cùng nội dung | ✅ không lỗi |
| CSV UTF-8 **có BOM** | ✅ không lỗi |
| CSV UTF-8 **không BOM** | ❌ mọi dòng tiếng Việt sai |

**Nguyên nhân gốc.** `src/app/api/admin/neighborhoods/import/route.ts:53`:

```ts
wb = XLSX.read(Buffer.from(await file.arrayBuffer()), { type: "buffer" });
```

Với `.xlsx` thì mã hoá nằm trong chính file nên không sao. Với CSV, SheetJS phải tự đoán bảng mã;
không có module `cptable` nó mặc định latin-1, trừ khi file có BOM.

**Ảnh hưởng.** CSV xuất từ Google Sheets hoặc soạn tay đều không có BOM → không bao giờ import
được. Popup import ghi rõ "Nhận .xlsx / .csv" nên người dùng có quyền dùng CSV.

**Cách sửa.** Tự giải mã UTF-8 khi là CSV, ở **cả hai** route
(`neighborhoods/import` và `suggestions/import`):

```ts
const buf = Buffer.from(await file.arrayBuffer());
const isCsv = /\.csv$/i.test(file.name) || file.type.includes("csv");
wb = isCsv
  ? XLSX.read(buf.toString("utf8").replace(/^\uFEFF/, "")   // bỏ BOM nếu có, { type: "string" })
  : XLSX.read(buf, { type: "buffer" });
```

**Nghiệm thu.** Nạp CSV không BOM có dấu tiếng Việt → nhãn dòng hiển thị đúng dấu, dòng hợp lệ
không báo lỗi geo. Nạp lại `.xlsx` và CSV có BOM → vẫn chạy như cũ.

## B2 · Ô "ngày treo" dùng chung một biến cho mọi dòng

**Nguyên nhân gốc.** `src/components/admin/SignsPanel.tsx:21` khai báo **một** state cho cả khối:

```ts
const [installDate, setInstallDate] = useState("");
```

Dòng 135 và 138 dùng lại đúng biến đó bên trong `produced.map(...)`.

**Hậu quả.** Nhập ngày ở dòng A rồi bấm "Đã treo biển" ở dòng B sẽ ghi ngày của dòng A. Ngược
lại, gõ ngày cho một dòng làm ô ngày của mọi dòng khác cùng đổi theo — admin rất dễ ghi sai ngày
treo mà không nhận ra.

**Cách sửa.** Chuyển sang map theo id:

```ts
const [installDate, setInstallDate] = useState<Record<string, string>>({});
// input:
value={installDate[s.id] ?? ""}
onChange={(e) => setInstallDate((d) => ({ ...d, [s.id]: e.target.value }))}
// nút:
act(s.id, "installed", { installed_date: installDate[s.id] || undefined })
```

**Nghiệm thu.** Có ≥2 dòng ở khối "Đang sản xuất": nhập ngày khác nhau cho từng dòng, ô này
không ảnh hưởng ô kia; treo biển xong kiểm `suggestions.installed_date` đúng từng dòng.

# PHẦN C — Nhỏ và sai lệch Figma

## C1 · Letter-spacing tiêu đề bị `.kp-h2` đè, không ăn utility Tailwind

**Hiện tượng.** Cả tiêu đề hero lẫn tiêu đề section đều đang có `letter-spacing: -0.4px` (= -1%),
trong khi Figma ghi hero **-3%** và section **-2%**.

**Nguyên nhân gốc.** Markup đã ghi đúng ý định:
- `HomeShell.tsx:301` → `tracking-[-0.03em]`
- `ui.tsx:140` → `tracking-[-0.02em]`

Nhưng `src/app/globals.css:294` khai báo:

```css
.kp-h2 { … letter-spacing: -0.01em; line-height: 1.15; }
```

`.kp-h2` nằm **ngoài `@layer`** nên thắng utility của Tailwind. Đây đúng là cái bẫy đã được ghi
trong `CLAUDE.md` cho `line-height` — nhóm trước đã xử lý line-height bằng class riêng nhưng
**bỏ sót letter-spacing**.

**Cách sửa.** Bổ sung vào khối class riêng đã có sẵn (`globals.css:305–317`), khai báo sau
`.kp-h2`:

```css
.kp-hero-title { letter-spacing: -0.03em; }
.kp-sec-title  { letter-spacing: -0.02em; }
.kp-lead-title { letter-spacing: -0.02em; }
```

**Nghiệm thu.** `getComputedStyle` của `h1` hero cho `-1.2px` ở cỡ 40px; tiêu đề section cho
`-0.8px`.

## C2 · `.kp-input` cao 44px, Figma vẽ 40px

**Nguyên nhân gốc.** `src/app/globals.css:324` dùng `padding: 9px 16px` + viền 1.5px nên chiều
cao thực ~44px. Chú thích ngay trên (dòng 320) ghi rõ ý định là **cao 40**, và `.kp-input-lg`
(dòng 336) đã làm đúng bằng `height: 50px` cố định.

**Cách sửa.** Đặt chiều cao cố định cho `.kp-input` giống `.kp-input-lg`:

```css
.kp-input { height: 40px; padding: 0 16px; }
textarea.kp-input { height: auto; padding: 9px 16px; }
```

Giữ `font-size: 16px` ở mobile (chống iOS tự phóng to) và hạ 14px từ `sm` như hiện tại.

**Nghiệm thu.** Bốn ô trong khối ưu đãi cao đúng 40px ở desktop, vẫn ≥44px vùng chạm ở mobile.

## C3 · Slider vẫn tự chạy khi bật "giảm chuyển động"

**Nguyên nhân gốc.** `src/components/home/NeighborhoodSlider.tsx:76` đặt `setInterval` 4 giây,
chỉ kiểm tra `document.visibilityState`, không kiểm tra `prefers-reduced-motion`. CSS ở
`globals.css:424` mới chỉ tắt `.slide-up` và `.heart-pop`; dòng 125 của slider có
`motion-reduce:transition-none` nên hiệu ứng trượt tắt **nhưng ảnh vẫn nhảy** mỗi 4 giây — với
người nhạy cảm chuyển động thì còn khó chịu hơn trượt mượt.

**Cách sửa.**

```ts
const reduced = typeof window !== "undefined"
  && window.matchMedia?.("(prefers-reduced-motion: reduce)").matches;
useEffect(() => {
  if (!multiple || reduced) return;
  …
}, [next, index, multiple, reduced]);
```

**Nghiệm thu.** Bật "Reduce motion" trong macOS → slider đứng yên, mũi tên ‹ › vẫn bấm chuyển
được. Đây là **E2E-6 mục 3** trong `docs/19`.
